- 요구사항: R03 연계 확장, R05 관리 설치 계약 재사용, R08 반응성과 작업 수명

## 사용자 결과

사용자가 선택적으로 로컬 검색 모델을 설치하고 검색할 폴더를 켠다. 파일명과 함께 자연어로 영상 내용·장면·소리를 검색하고, 결과에서 근거 썸네일/자막·일치 시점으로 영상 상세와 재생을 연다. 기존 파일명 검색은 모델 없이 즉시 사용할 수 있다. 현재 기능 구현이 아니라 후속 계획이다.

## 계약과 범위

2026-10-17 확인한 [Google 공식 모델 카드](https://huggingface.co/google/embeddinggemma-2)는 EmbeddingGemma 2가 텍스트·이미지·영상·오디오를 공통 벡터로 표현하는 모델이라고 설명한다. 이 모델을 우선 평가 후보로 기록하되 채택 확정은 아니다. 설치할 revision·파일·hash·tokenizer/전처리·라이선스와 Windows Rust/native 추론 지원을 실제 공급물로 검증한다. 모델은 다운로드 도구와 역할을 구분한 선택 구성요소이며 기본 앱 설치/실행에 포함하지 않는다. 비디오 검색이 가능하다는 모델 설명이 dlpad에서 임의 길이 영상을 정확히 검색한다는 인수 증거는 아니다.

수직 작업 순서:

1. 합성/공개 검증 영상으로 한국어 질의·장면/오디오 검색 품질, 지원 native backend, CPU/GPU별 지연·RAM/VRAM·설치 크기를 측정한다. 자막/제목 텍스트 검색과 실제 영상/오디오 내용 검색의 범위·비용을 따로 표시한다. 영상 전부 메모리 적재 없이 FFmpeg의 bounded 구간/프레임·오디오 sampling을 사용하고 긴 영상의 누락/샘플링 한계를 공개한다. 모델 dimension/정밀도/추론 backend는 실측 후 ADR로 채택한다.
2. 설정에서 모델 설치·버전 조회·pin·검증·제거, 설치 크기와 예상 작업 비용, 필요한 구성요소로 이동하는 UX를 제공한다. 설치/업데이트는 사용자가 시작하며 자격 증명 자동 사용·외부 영상/검색어 전송은 하지 않는다. 외부 모델 경로는 제거하지 않고 관리 설치만 원 identity 검증 후 정리한다. 모델 제거와 검색 인덱스 삭제는 별도 선택이며 미디어는 보존한다.
3. 폴더별 검색 활성화/일시정지/재색인/인덱스 삭제와 용량·대기/처리/오류/부분 색인 상태를 제공한다. 파일명/의미/혼합 검색을 구별하고 결과마다 검색 근거와 일치 시간 범위를 표시한다. 원 다운로드·라이브러리 scan·재생의 반응성을 우선하며 queue·동시 worker·RAM·cache·DB·임시 추출물 상한, 취소·시작 복구를 둔다.
4. 아래 동기화 계약과 실패 인수를 통과한 뒤 앱에 연결한다. Cargo/DB 변경은 Root가 조정하고 inference·index·UI 파일 소유를 나눈 후에만 병렬화한다.

폴더/색인 동기화 제안:

- 파일시스템이 원본이며 인덱스는 다시 만들 수 있는 앱 소유 파생 자료다. 다운로드 이력만 색인하지 않고 외부에서 추가된 영상도 같은 라이브러리 경로로 관측한다. 원본에 sidecar를 강제로 쓰거나 이름/내용을 바꾸지 않는다.
- 모델 revision·전처리/sampling version·벡터 차원과 원 파일 identity·콘텐츠 generation·구간 시간을 인덱스에 묶는다. path/mtime/size만으로 동일 콘텐츠라 확정하지 않으며 파일 ID 재사용·동일 크기 교체를 별도 처리한다. 긴 파일 digest 검증도 bounded streaming/cancellation으로 수행한다.
- rename/move는 기존 R03의 유일한 native identity 관측 조건에 맞을 때만 경로를 갱신하고 벡터를 재사용한다. 제목을 입력으로 포함한 벡터는 제목 변경 시 해당 부분을 재색인한다. hardlink·중복 identity·폴더 간 이동이 불명확하면 별도 관측으로 처리하고 임의 병합하지 않는다.
- 추가/수정은 debounce된 bounded queue로 합치고 미완료 .part나 기록 중인 파일은 안정화 뒤 처리한다. 읽기 전후 identity/content generation을 다시 검사하며 중간 변경·취소·삭제 시 그 generation을 게시하지 않는다. 이미 게시한 다른 파일/기존 완료 인덱스는 유지한다.
- 삭제는 성공한 scan 범위에서만 missing을 확정하고 해당 결과를 검색에서 제외한다. 폴더 권한 거절·드라이브/네트워크 분리·일시적 watch 손실은 삭제로 간주하지 않는다. 이벤트는 힌트이며 주기 reconciliation과 재연결 scan으로 복구한다.
- 모델 업데이트/차원·sampling 변경은 별도 generation을 만들고 완료된 항목만 원 파일 최신 generation과 원자적으로 전환한다. 서로 다른 모델 벡터는 같은 거리 검색에 섞지 않는다. 재색인 중 기존 사용 가능한 검색과 새 모델 진행 상태를 구별한다. 이전 모델/인덱스 회수는 active query/worker의 사용 종료 뒤 수행한다.

## 인수 조건

- 파일명과 무관한 한국어 질의로 검증된 영상/구간을 찾고 기본 앱 재생 경로로 연결한다. 텍스트-only 색인을 영상 자체 이해 완료로 보고하지 않는다.
- 외부 추가·rename·move·수정·동일 크기 교체·삭제·hardlink·권한 거절·볼륨 분리/복귀·watch overflow·동시 scan/색인·미완료 다운로드·worker 도중 변경을 합성 폴더로 시험한다.
- 취소·앱 종료/crash·디스크 부족·모델 다운로드/검증 실패·업데이트 중단·손상 인덱스에서 원 미디어를 보존하고 제한된 재개/재색인으로 복구한다. 권한 오류 때 일괄 삭제·외부 전송은 0이다.
- 실제 설치 크기·색인 디스크 증가·분당 처리 시간·검색 지연·RAM/VRAM·백그라운드 CPU를 측정하고 한글/긴 경로·저사양 Windows에서 UI 응답을 확인한다. 예산과 품질 통과값은 실험 뒤 확정한다.

## 검증과 handoff

계획만 작성했다. 모델/추론 의존성 다운로드·설치·코드·schema 변경0, 비용 실측/모델 채택/실행 인수는 아직 없다. 다음 결정은 native backend 지원과 한국어 멀티모달 검색 품질·비용 실험이며 현재 진행 중인 CI 버그 수정을 중단하거나 P0 범위를 늘리지 않는다.
