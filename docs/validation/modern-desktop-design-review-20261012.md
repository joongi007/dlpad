# Windows UI 품질 및 GTMUX 대조

## 조사 기준

사용자는 다른 작업 옆에서 다운로드 상태를 확인하고 필요한 경우 설정을 조정한다. 컴팩트한 작업 화면, 조용한 상태 표시, 예측 가능한 기본값을 우선한다.

- [Fluent 2 layout](https://fluent2.microsoft.design/layout): 간격으로 관련 요소를 묶고 계층을 만들며, 일관된 간격 리듬을 사용한다. 모든 요소에 같은 여백을 반복하는 것은 그룹 관계를 흐릴 수 있다.
- [Fluent typography](https://fluent2.microsoft.design/typography): 제목·본문·보조 정보의 역할을 크기와 무게로 구별하고 글자 기준선을 정렬한다. Windows에서는 시스템 글꼴을 활용한다.
- [Windows forms](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/forms): 입력의 의미에 맞는 조작을 선택하고 라벨·힌트·오류를 연결한다. 숫자·선택값을 모두 자유 텍스트로 요구하는 흐름은 입력 부담을 높인다.
- [Progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/): 자주 쓰는 동작을 먼저 보여주고 덜 쓰는 세부 제어를 필요할 때 공개한다. 중요한 오류와 현재 상태는 숨기지 않는다.

## 현재 화면에 대한 판단

이는 출처의 일반 원칙을 실제 dlpad source 및 root가 본 PNG에 적용한 판단이다. Windows 공식 시스템이나 GTMUX의 모든 화면을 동일하게 재현했다는 주장은 아니다.

1. 설명·기술 상태·버튼의 시각적 비중이 비슷하다. 사용자가 할 일보다 긴 설명과 측정 불가 문구가 먼저 눈에 들어온다.
2. 고급 옵션은 설명·기본값·예시·충돌·버전의 반복으로 세로 길이가 커졌다. 모든 정보를 상시 노출해 설정의 우선순위가 흐려졌다.
3. 파일 목록 안내가 버튼 행에서 단어 단위로 끊겼다. 별도 안내 행으로 수정했고 원 PNG에서 개선을 확인했다.
4. 숫자의 단위와 기본 동작을 알아야 입력할 수 있다. 기본값 표시와 복귀를 먼저 적용했으며 속도 제한의 사용자 단위 조작을 후속으로 개선한다.
5. Windows 미지원 관측 상태를 상시 측정 불가로 표시해 앱 오류처럼 보인다. 실제 기능 연결과 상태별 문구가 필요하다.
6. 설치 버튼의 글자 문제는 사용자 제보이며 아직 원인을 재현하지 못했다. 글리프와 실제 paint clip을 캡처로 구분한다.

## GTMUX 대조

실제 /mnt/d/project/gtmux/codebase/frontend/src/styles/tokens.css와 lib/ui/Button.svelte를 읽었다. 원본은 기본32px/보조24px 버튼, 역할별 표면·테두리·accent, 제한된 primary 행동, 정렬된 기준선과100ms 상태 피드백을 사용한다. dlpad는 색 토큰 일부를 따랐지만 화면의 정보 밀도와 제어 선택은 별도로 조정해야 한다. CSS 기술을 Rust에 복제하는 것으로 이 문제를 해결할 수 없다.

## 다음 구현 기준

- 첫 실행에 저장 위치와 주요 정책을 채워 URL 입력 후 필요한 행동이 명확하다.
- 다운로드 시작·설치 등 화면의 주 동작을 하나로 구별한다.
- 설정은 짧은 라벨과 현재 값 중심, 설명은 접근 가능한 상세에 둔다.
- 숫자 입력에는 단위와 기본값을 제공한다. 고급 설정도 기본값 복귀가 가능하다.
- 선택·hover·focus·disabled·작업 중·오류를 같은 컴포넌트 규칙으로 표현한다.
- 상태줄에는 지금 의미 있는 상태를 우선한다. 지속적인 미지원 경고를 정상 상태처럼 반복하지 않는다.
- 변경 중에는 관련 실패 회귀를 확인하고, 작업 묶음 통합 시 전체 필수 검증을 수행한다. 원 실패와 미검증 조건은 유지한다.

Windows에 집중하며 Linux/macOS 신규 구현은 후속 범위다. 고급 옵션 UX, 설치 버튼 재현, Windows 관측 연결을 먼저 통합한다. 전체 UI 현대화와 사용자 인수는 미완료다.
