# S00 네이티브 실측

2026-09-30 WSL2 Linux x86_64 / WSLg X11, 960×640, 100% 배율, Rust 1.94.0, release opt-level=s/thin LTO/strip. 기존 Windows 한글 폰트를 검증 프로세스에서만 읽었고 배포물에는 넣지 않았다. 문서의 목표와 측정값을 구별한다.

## 초기 동일 목록 비교

| 구성 | 비압축 실행 파일 | 대기 RSS | 대기 CPU 표본 | 실제 창 |
|---|---:|---:|---:|---|
| Iced tiny-skia 초기 spike | 6,226,232 bytes | 67,724 KiB | 5초 0% | 실행/한글 글리프 표시 |
| eframe 0.33.3 Glow/AccessKit | 8,797,248 bytes | 134,808 KiB | 5초 0% | 실행/한글 글리프 표시 |
| Iced wgpu | 9,884,320 bytes | 측정 실패 | 측정 실패 | surface configure 오류, exit 101 |

스크린샷과 원시 JSON은 [software](iced-software.json), [egui](egui-glow.json), [GPU 실패](iced-gpu.json), [GL 재확인 실패](iced-gpu-gl.json)에 있다. GPU backend 변경과 자체 shader cache 경로로 재확인해도 Invalid surface가 발생했다. egui RSS는 초기 80 MiB idle 목표를 초과한다. tiny-skia의 접근성 bridge는 확인하지 못했다.

이 숫자는 초기 비교 화면이다. 기능을 추가한 최신 개발 UI는 별도로 재측정한다. 표본이 짧고 100Hz CPU tick 해상도가 있으므로 장시간 idle 1% 예산 달성을 증명하지 않는다. 앱만 측정했으며 외부 미디어 도구 비용은 포함하지 않는다.

## 검증과 제한

`python3 scripts/native_probe.py <binary> <output.json> --seconds 5`는 합성 10,000행 viewport를 실행하고 자신의 프로세스를 종료·회수한다. 사용자 Documents와 영상은 사용하지 않았다. Windows 폰트를 읽은 Linux 글리프 검증은 Windows 앱 검증이 아니다.

미검증: 실제 한글 조합/IME, OS clipboard 동작, 스크린리더, 150/200% 시각 검수, 실제 OS theme change/첫 프레임, scroll/background CPU, 8시간 soak, GPU/driver 장비 matrix, Windows/macOS 런타임과 원격 CI. 정상 Git/remote가 없어서 CI를 실행하지 않았다.

결정: Rust 네이티브 제약 유지. 개발 기본 tiny-skia로 지속 실험하지만 최종 Iced/egui 선택과 ADR Accepted 전환은 보류한다. 부족한 S00 증거를 foundation unit tests로 대체하지 않는다.

## 중단 후 재개와 가상 화면 시험

[재개 검증](resume-validation.md)에서 현재 통합 앱을 다시 빌드하고 측정했다. 사용자 데스크톱을 방해하지 않도록 probe 기본값을 Xvfb로 바꿨다. Xvfb가 없으면 실패하며 desktop fallback을 하지 않는다. `--desktop`은 사용자의 명시적 요청이 있어야 사용한다. Xvfb 수치는 실제 WSLg/OS IME·접근성 증거를 대체하지 않는다.
