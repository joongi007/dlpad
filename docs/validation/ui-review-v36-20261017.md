# v36: 탐색기 파일 선택의 Windows 경로 처리 수정

상태: done-scoped / 사용자 선택 화면 검수 대기. v35 사용자 실사용의 기본 앱 열기 성공/탐색기 선택 오류를 대상으로 한다.

## 원인과 수정

Windows에서 파일 검증에 쓰는 canonical `\\?\D:\…` 경로를 Shell 파서에도 그대로 전달했다. 실제 합성 native 실험 두 번에서 같은 파일의 ordinary 경로는 성공하고 verbatim 경로는 ILCreate NULL·SHParse E_INVALIDARG(0x80070057)로 실패했다. 첫 실험은119/123UTF16, 재실험은119/123 및371/375UTF16이다. 실제 사용자 선택 창은 열지 않았다.

Reveal에 한해 Shell에 전달할 경로 표기를 바꾸고, 원 retained 파일/부모 nativeID와 canonical directory entry가 같을 때만 사용한다. 다른 항목으로 해석될 수 있는 trailing-dot/space alias는 거절한다. PIDL은 SHParseDisplayName으로 생성하고 CoTaskMemFree로 한 번 해제한다. File/ChooseApplication 분기와 Default desktop·외부 Explorer·Job·취소·기한 계약을 바꾸지 않는다.

제품 수정은 `crates/app/src/library_open.rs`, `crates/app/src/external_open_broker.rs` 두 파일이다. Cargo workspace/lock/schema/의존성/UI 레이아웃 변경은 없다. 추가 메타데이터 조회와 alias 할당은 사용자가 탐색기 선택을 요청했을 때의 기존 worker에서만 수행한다. 별도 상주 thread나 다운로드는 없다.

## 검증

실제 broker 인수 경계의 회귀를 먼저 실행해 canonical 입력 노출로 실패하는 RED를 보존했다. 수정 후 관련16회귀가 통과했다. 실제 production PIDL 파서의 한글·공백·기호/260자 초과 경로 roundtrip 및 다른 항목 alias 거절을 확인했다. Windows whole36의 네 Cargo 명령은 실제 성공했고 총계는 1685/0/42·43harness다. Root가 source675·원 로그·3PE·lock과 새 설치/portable ZIP의 전체 CRC/SHA·graph258/notice456을 대조했다.

별도 읽기 전용 COM 실험은 기존 같은세션 Explorer가 있을 때 위치 VT_EMPTY와 VT_I4(0) 모두 S_OK·dispatch를 반환했다. private desktop의 HWND PID 조회 불가를 정상 desktop의 제품 실패로 확대하지 않았다. 원 Explorer는 같은 PID/creation·Job 밖 상태를 유지했다. 사용자 창 열기/선택/이동/desktop 전환/전역 입력0이다.

## 제한

실제 사용자 Explorer의 선택 완료는 자동 시험에서 수행하지 않았다. private 실제 파싱/원 파일 대조/요청 경계 검증과 사용자 desktop 선택 화면 인수를 구분한다. 이전35의 설치·재설치·GUI와33의 성능·긴 경로·로컬CI는 각 snapshot 기록으로 유지한다. 이번 수정에서 반복 시험했다고 표시하지 않는다. 자동 앱 교체/업데이트·전체 P0 완료는 아니다.
