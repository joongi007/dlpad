2026-10-11 통합 중인 앱 포함 설치 후보는 설치 위치 하나를 입력하거나 **상위 폴더 선택**으로 고르는 방식이다. 명세·원본은 묶음에 포함되어 내부에서 고정하며, 설치 기록은 같은 상위 폴더의 `.<설치폴더이름>-install-journal`에 자동으로 만든다. 선택한 기존 상위 폴더 자체를 덮어쓰지 않고 그 안의 새 `dlpad-preview`를 제안한다. 신규 전체 검사와 private GUI 인수 후 제공할 후보이며 아래 이전 개발 ZIP에 소급하지 않는다.

# Windows 개발용 설치 화면

`dlpad-install.exe`는 로컬 개발 묶음을 새 폴더에 설치하고 현재 파일을 다시 검증하며 명시적으로 제거하는 Rust 네이티브 화면이다. 정식 배포 설치 프로그램의 완료를 뜻하지 않는다. [검증 범위](../work-items/S07-windows-native-development-bootstrap.md)와 [CLI 안내](windows-local-install.md)를 함께 읽는다.

Windows MSVC release 빌드의 `dlpad-install.exe`를 실행한다. 새 설치에는 다음 네 경로를 입력한다. 경로는 로컬 드라이브의 절대 경로여야 한다.

| 입력 | 선택할 대상 |
|---|---|
| 설치 명세 파일 | 준비한 개발 묶음의 manifest 파일 |
| 원본 파일 폴더 | 명세에 기록한 실행 파일과 notice가 있는 폴더 |
| 설치 폴더 | 새 설치에는 기존에 없는 대상 폴더, 기존 설치 검사에는 현재 bundle 폴더 |
| 외부 단계 기록 폴더 | 새 설치에는 기존에 없는 별도 journal 폴더, 검사에는 해당 bundle의 현재 journal 폴더 |

설치 명세 옆의 파일 선택 버튼으로 기존 로컬 JSON 파일 하나를 고를 수 있다. 선택은 명세 입력만 바꾸며 설치를 자동 시작하지 않는다. 취소는 기존 입력과 검증 상태를 보존한다. [파일 선택 검증](../work-items/S07-windows-native-manifest-picker.md).

상위 폴더는 먼저 존재해야 한다. 명세와 원본은 같은 묶음을 사용한다. 현재 화면에는 폴더 선택 버튼이나 기본 설치 경로가 없다. `--manifest`, `--source-dir`, `--bundle-root`, `--journal-root` 인자로 네 입력을 미리 채울 수도 있다. 인자만으로 설치를 시작하지 않는다.

**설치**를 선택하면 worker가 원본 SHA와 경로를 검사하고 복사·등록·선택 단계마다 기록을 남긴다. 완료 후 **다시 검증**으로 현재 설치 파일과 기록의 일치를 확인한다. 이미 존재하는 대상 폴더에는 덮어쓰지 않는다. 새로 실행한 화면에서 기존 설치를 검사할 때는 **설치 폴더**와 **외부 단계 기록 폴더**만 입력하고 **다시 검증**을 선택한다. 원본과 명세 입력은 비워도 된다. 화면 시작이나 경로 입력만으로 설치·검증·제거를 자동 실행하지 않는다. 검사 성공 후 **제거 요청**을 사용할 수 있으며 확인 시점에 현재 설치를 다시 검사한다. 두 경로를 미리 채우는 별도 CLI 인자는 추가하지 않았다.

**중단 요청**은 worker에 취소를 전달한다. 작업 중 창을 닫아도 worker 종료를 확인할 때까지 기다린다. 중단·시간 초과·오류로 만들어진 파일과 기록은 보존한다. 같은 대상 경로에 자동으로 이어 설치하거나 부분 자료를 자동 삭제하지 않는다. 오류 문구를 확인하고 명세·원본·권한 또는 새 대상 경로를 수정한다.

화면은 Windows 시스템 표준 컨트롤과 폰트를 사용한다. 격리 데스크톱에서 설치·재검증·기존 폴더 거절·복사 중 취소·닫기·잘못된 SHA를 실제 검증했다. 물리 한글 IME·스크린리더·DPI·최소 OS·clean OS·서명·upgrade 인수는 남아 있다.

제거 UI는 Windows 전체 검사와 실제 격리GUI의 확인 취소·정상 제거·foreign/경로수정 거절·취소/닫기 ACK 및 기존 설치 회귀를 인수했다. 결과와 남은 범위는 [제거 UI 작업](../work-items/S07-windows-native-development-removal-ui.md)에 기록한다. 현재 설치의 **다시 검증**이 성공하면 **제거 요청**을 선택할 수 있다. 입력한 설치 폴더의 고정 파일만 제거한다는 안내를 확인하고 **제거 확인**을 선택하면 worker가 현재 bundle과 외부 journal의 일치를 다시 검사한다. **돌아가기**나 확인 중 창 닫기는 제거를 시작하지 않는다. 확인 중 경로 입력은 잠기며, 경로를 수정하면 다시 검증해야 한다. 원본·manifest·외부 journal·앱 data·영상·외부 도구는 제거 대상이 아니다.

제거 작업 중 **중단 요청**이나 창 닫기는 종료 확인을 기다린다. 이미 제거된 파일을 복구하지 않으며 일부 제거 가능성과 시작 전 거절을 구분해 표시한다. 설치 파일 제거 완료는 설치 폴더의 실제 부재를 확인했을 때만 표시한다. worker 종료 후 UI에 원 handle 재시도 권한을 보관하지 않으므로 부분 결과를 자동 복구하거나 자동 정리하지 않는다.

기존 설치 재시작의 실제 두 프로세스 시험·확인 취소/제거, 기존 설치·제거 실패 회귀 및 최신 성능 결과는 [기존 설치 재검증 작업](../work-items/S07-windows-native-existing-bundle-reverify.md)을 따른다.

현재 검증한 세 실행 파일을 함께 담은 [개발 ZIP](../validation/evidence/windows-msvc-native-installer-companion-graph-20261006-continue/dlpad-native-installer-development-a.zip)을 로컬에서 사용할 수 있다. 검증 SHA·notice 및 정식 배포 미완료 범위는 [개발 ZIP 작업](../work-items/S07-windows-native-installer-companion-package.md)을 따른다. 이 ZIP은 서명된 정식 설치·updater의 완료를 뜻하지 않는다.

## 직접 사용 확인

자동 시험 뒤에도 사용자의 직접 UI/UX 확인이 필요하다. 현재 ZIP은 수동 경로 입력을 사용하는 이전 검증 후보이며, 소스에 통합 중인 명세 파일 선택 버튼은 포함하지 않는다. 새 후보는 빌드와 격리 시험을 통과한 뒤 실행 방법·버전·알려진 제약과 함께 제공한다. 사용자 화면에서 자동으로 실행하지 않는다.

직접 확인할 때는 별도 임시 폴더와 합성 자료를 사용한다.

- 설치 안내와 오류 문구를 이해할 수 있는지, 설치·검증·제거 확인이 명확한지 확인한다.
- 앱 첫 실행에서 한글 입력, 목록 탐색, 옵션 선택과 취소가 자연스러운지 확인한다.
- 숨김·복귀와 재시작 후 설정 및 상태가 예상대로 보이는지 확인한다.
- 진단 화면에서 문제를 파악하고 보고서를 저장할 수 있는지 확인한다.
- 실제 사용하는 배율과 키보드 탐색에서 잘림·초점 이동·읽기 어려운 문구를 기록한다.

직접 평가와 수정 후 재확인을 별도 인수로 기록한다. [사용자 인수 작업](../work-items/S00-windows-user-acceptance.md)은 아직 진행 중이다.
