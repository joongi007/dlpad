# 구현 순서

> 사용자 범위 변경: 최초 릴리스는 **Windows 우선**이다. Linux·macOS 및 3OS 출시 인수는 후속으로 보류한다. 기존 문서의 3OS 게이트는 후속 목표이며 Windows P0 완료를 차단하지 않는다. 공통 Rust 구현과 기존 검증 근거는 유지한다. [범위 계약](work-items/P0-windows-first-release.md).

각 단계는 UI→application→저장/도구→실패 복구까지 연결하는 수직 기능이다. 단계별 완료 게이트는 유지한다. S00의 Linux 측정과 독립 P0 기반 구현을 진행했으나 어느 출시 단계도 완료로 선언하지 않았다. 상세 상태는 [현재 구현 상태](validation/P0-status.md)에 있다. S08/S09와 외부 분석 확장은 아직 미착수다. 선행 기능을 갖춘 UI·설치의 국소 개선은 개별 작업 계약으로 진행했으며, 이를 전체 P0 또는 후속 단계 완료로 집계하지 않는다.

| 단계 | 사용자 결과 | 완료 게이트 / 의존 |
|---|---|---|
| S00 | 네이티브 화면·테마·입력 | Windows renderer/IME/접근성/크기 측정·CI. ADR-0001 채택; 다른 OS는 후속 |
| S01 | 저장 위치와 파일 목록 | 문서 폴더 생성, 외부 추가·삭제·권한 실패, DB migration. S00 |
| S02 | URL 한 개 다운로드 | external yt-dlp 감지, 메타데이터, 진행률, 프로세스 트리 취소, 최종 파일 등록. S01 |
| S03 | 긴 작업 중단·복구·백그라운드 | crash·sleep·URL 만료·8시간 soak, 닫기 정책, 고아 프로세스 검증. S02 |
| S04 | 도구 자동 설치와 관리 | manifest·검증·rollback·버전 pin·제거, FFmpeg 공급처 확정, JS runtime. S02 |
| S05 | 구간·품질·고급 옵션 | 빠른/정확한 자르기, 주요 카탈로그, 충돌 검증, 비용 설명. S03/S04 |
| S06 | 상태·설치·접근성 완성 | 네트워크/디스크/처리 지표, Windows 패키지·제거 흐름, 성능 예산; 다른 OS는 후속. S01–S05 |

| S08 | P1 확장 | config 가져오기, 라이브 녹화, 환경 benchmark, 사이트별 안정화 |
| S09 | P2 YouTube 업로드 | OAuth/프로젝트 준비, resumable worker, privacy와 ambiguous completion 시험 |

S07 출시 게이트에는 S10의 P0 진단 자료 기능도 포함한다. S10 번호는 S09 다음에 구현한다는 의미가 아니다.

## 아직 검증하거나 결정할 사항

- Windows Rust 네이티브 CPU 후보의 최종 스택 채택, 실제 IME·reader·DPI 인수와 목표 성능/메모리/크기. 과거 Iced 검토와 현재 후보의 검증 범위를 구분한다.
- 창 닫기 기본값. 사용자 답변 전에는 작업 중 확인으로 설계.
- Windows 최소 OS와 clean runtime·설치/제거 인수. Linux 배포 호환성·다른 OS/ARM64 범위는 후속.
- FFmpeg 관리 설치·버전 검증·합성 구간 시험의 완료 범위와 별도로 남은 공급 trust/배포물 라이선스 인수, 서명 인증서와 예산.
- GitHub 저장소·소유자·배포 채널. 현재는 로컬 문서만 있고 remote 연결하지 않음.
- YouTube 업로드의 공용 OAuth 프로젝트 운영자, 검증·감사 준비. 지원 전에 확정.

확정되지 않은 사항은 다음 작업에서 증거를 얻고 결정한다. 문서 준비 완료가 위 기능들의 구현 완료를 의미하지 않는다.

## 사용자 지정 후속 순서 (2026-10-03)

기능 완성·실패 경로 및 OS 검증을 마친 뒤 Git 저장소에 반영하고 CI/CD를 연결·실행한다. 그 다음 [앱 updater](work-items/S11-app-updater.md)를 구현한다. updater는 사용자 지정 후속 범위이며 현재 P0 완료를 대신하는 작업이 아니다. 저장소/채널/서명과 OS별 교체·복구 정책은 선행 실제 결과를 근거로 정한다.
